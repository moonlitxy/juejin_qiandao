# 掘金自动签到插件 - 使用说明

本文档面向使用者，介绍插件的安装、每块界面怎么用、自动签到的触发规则，以及常见问题。
开发相关说明见 [../CLAUDE.md](../CLAUDE.md)，5 分钟上手见 [QUICKSTART.md](QUICKSTART.md)。

---

## 1. 安装

1. 打开 Chrome（或 Edge / Brave 等 Chromium 内核浏览器），地址栏输入 `chrome://extensions` 回车。
2. 打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本项目文件夹。
4. 打开 <https://juejin.cn> 登录掘金账号——插件靠浏览器里的登录态（cookie）签到，**没登录无法签到**。
5. 点击工具栏中的插件图标（⛏️），点「📝 立即签到」验证一次。

> 扩展 ID 由 `manifest.json` 中的 `key` 固定，换电脑 / 重新加载后 ID 不变，抽奖记录的跨设备同步依赖这一点。

---

## 2. 插件弹窗

点击工具栏图标打开。弹窗会在打开时实时核对一次服务端签到状态，所以网页上签过的日期也能正确显示。

### 2.1 签到状态卡片

| 显示 | 含义 |
|---|---|
| ✓ 今日已签到 | 服务端确认今天已签 |
| 未签到 | 今天还没签 |
| ⏰ 签到中... | 签到流程进行中（可能已转入自动重试） |
| ✗ 签到失败 | 本次签到失败，失败原因显示在下方文字里 |

下方统计三项：

- **连续签到天数**：以掘金服务端数据为准。
- **本月签到天数**：以掘金服务端本月明细统计为准。
- **累计签到天数**：以掘金服务端数据为准，即你在掘金的历史总签到天数（网页端「累计签到」同一个数）。
- **当前矿石**：实时查询服务端，签到 / 抽奖后会自动刷新；未登录或查询失败时显示 `-`。

### 2.2 抽奖结果

签到成功后会自动使用当天的**免费**抽奖次数。如果抽到奖品，状态卡片下方会显示当天抽中的奖品。当天没有中奖记录时这一块不显示。开启「同步云端抽奖」后，由 GitHub Actions 负责抽奖，本机不重复抽奖，结果会自动拉取并显示。

### 2.3 操作按钮

- **📝 立即签到**：立即执行一次签到，忽略「自动签到」开关（手动操作始终放行）。签到转入后台重试时按钮会保持「签到中...」，最长等待 90 秒。
- **🔗 打开掘金**：在新标签页打开掘金首页，可用来确认登录状态。

### 2.4 快速设置

- **自动签到**：总开关，关闭后定时签到和过点补签都不会执行。
- **签到时间**：每天自动签到的时刻。修改即时保存，并会同步显示在设置页。

点击右下角「⚙️ 设置」进入完整设置页。

## 3. 设置页

### 3.1 自动签到

| 选项 | 说明 | 默认 |
|---|---|---|
| 启用自动签到 | 关闭后所有自动签到（定时、补签）停止，手动签到不受影响 | 开 |
| 签到时间 | 每天自动签到的时刻 | 09:00 |
| 自动抽奖 | 签到成功后自动用掉当天免费抽奖机会；关闭则只签到不抽奖 | 开 |

### 3.2 通知设置

| 选项 | 说明 | 默认 |
|---|---|---|
| 签到成功通知 | 签到成功时弹桌面通知 | 开 |
| 签到失败通知 | 签到失败时弹桌面通知 | 开 |

### 3.3 高级设置

| 选项 | 说明 | 默认 |
|---|---|---|
| 签到重试次数 | 签到失败后自动重试几次（0～3）。每次重试都沿用同一个后台标签页 | 1 次 |
| 页面加载超时 | 等待掘金页面加载的最长秒数，网络慢时可调大 | 30 秒 |

### 3.4 签到日历

只读，数据来自掘金服务端本月明细。图例：

- 已签到 / 漏签 / 今天 / 未到（未来日期）

⚠️ **签到日历不能翻月**：掘金接口只返回当前这一段数据（约一个月），插件也不保存更早的本地记录，所以只能看到服务端给的当前区间。

### 3.5 签到历史

「最近的签到记录」列出最近 30 条本地记录。两个按钮：

- **重置今日状态**：清掉本地「今天已签到」标记，允许今天再签一次。一般只在本地状态显示错误、而你确认服务端确实未签时使用。
- **清空历史**：删除本地签到历史。

### 3.6 抽奖日历

按天展示抽奖结果，图例：中奖 / 未抽奖 / 失败 / 无记录。支持「上个月 / 下个月」翻月。

- **同步到其他设备**：开启后，抽奖记录通过 Chrome 账号同步。需在 Chrome 中登录同一账号并开启同步；未登录时同步会退化为仅本机保存，不报错。
- **本机抽奖回传 GitHub**：开启后，本机抽中的免费奖品会合并到仓库的 `.cloud/checkin-lottery.json`。需要填写 fine-grained PAT，只授予本仓库 `Contents: Read and write`；Token 只保存在本机，不会进入配置或 Chrome 同步。
- **云端结果仓库**：必须填写你自己的 `owner/repo`。默认留空，不会连接任何仓库；使用别人的仓库会看到别人的记录，且 Token 可能被误用于错误仓库。
- **清空抽奖记录**：同时清除本机记录与已同步到 Chrome 账号的记录。
- 只能在插件自己的抽奖记录范围内查看：**在掘金网页上手动抽的奖无法被记录**（掘金没有开放可用的个人抽奖记录接口）。

### 3.7 底部按钮

- **保存设置**：保存「自动签到 / 通知 / 高级设置」区域的所有选项。
- **重置设置**：把这些设置项恢复默认值，**不会**删除签到历史、连续天数、抽奖记录。

> 设置页和弹窗共享同一份配置：在一处修改（弹窗改即时生效，设置页需点「保存设置」），另一处若正打开会实时回显。设置页表单里有未保存的修改时，不会被外部改动覆盖。

## 4. 自动签到的触发规则

### 4.1 每日定时

到达「签到时间」时，插件会在后台打开掘金沸点页（`juejin.cn/pins`）自动完成签到，成功后关闭标签页。签到完成后自动抽奖。

**前提**：浏览器必须处于运行状态。浏览器关闭、电脑休眠期间闹钟不会触发。

### 4.2 过点未签补签

如果过了签到时间当天还没签到（比如当时断网、签到失败、浏览器刚启动），插件会**每 30 分钟检查一次**，没签就补签一次，直到签上为止；签上后当天停止巡查。

### 4.3 浏览器启动时补签

浏览器启动时如果发现「今天签到时间已过且还没签」，会立即补签一次，并重新校准定时闹钟（防止闹钟丢失或时间漂移）。同时会清理上次异常退出时残留的签到标签页。

### 4.4 多设备 / 网页签到

- 插件在签到前后都会与掘金服务端核对状态，网页上签过、其他电脑签过的**不会重复签到**，只会提示「今天已经签到过了」。
- 但「过点未签补签」的本地判断只看本机记录：如果今天是在网页上签的、本机没记录，补签会多走一次签到流程，最终由服务端判定为已签，结果正确，只是会多花一点时间。
- 每台电脑的本地数据相互独立；抽奖记录可通过 Chrome 同步共享（见 3.6）。

## 5. 常见问题

**Q：到了签到时间但没有签到？**
依次检查：自动签到开关是否开启；浏览器当时是否在运行（关闭或休眠期间不会触发）；是否已登录掘金；能否正常打开 juejin.cn。过点后插件会每 30 分钟自动补签，浏览器一直开着的话等一会儿再看，也可以手动点「立即签到」。

**Q：显示「请先登录掘金账号」？**
打开 <https://juejin.cn> 重新登录，然后重试。

**Q：登录后仍提示需要登录？**
切换 VPN / 代理或网络环境可能导致登录态丢失，重新登录即可。

**Q：签到成功但没有抽奖？**
- 检查「自动抽奖」是否开启；
- 当天免费次数已经用完时不会抽奖。为了不扣矿石，插件**只在有免费次数时抽奖**，绝不会在没有免费次数时消耗矿石。

**Q：抽奖日历里为什么没有网页上抽到的奖？**
掘金没有对普通用户开放抽奖记录接口，网页手动抽的奖无法获取，插件只记录自己抽的奖。

**Q：签到日历只能看到本月？**
掘金接口只返回当前这一段数据，无法按月查询历史，这是服务端限制。

**Q：弹窗里显示未签到，但我在网页上签过了？**
弹窗打开时会与服务端核对并自动纠正，稍等片刻或重新打开弹窗即可。

**Q：Chrome 扩展页面出现「此扩展程序包含密钥文件 .keys/xxx.pem」？**
这是开发者模式下加载含签名私钥的目录时 Chrome 给出的**提示，不是错误**，不影响使用。私钥仅用于把扩展打包成 `.crx`；只使用「加载已解压的扩展程序」的话不需要它，可以把它移出项目目录（如放到同级的 `juejin_qiandao-keys/` 目录），提示就不会再出现。注意不要删除后重新打包，否则扩展 ID 会变，跨设备同步的抽奖记录会对不上。

**Q：改了代码后插件行为没变化？**
在 `chrome://extensions` 点「重新加载」，并对后台服务点击「终止 / 重新加载 Service Worker」——Chrome 会缓存后台脚本，只重载页面不够。

## 6. 数据与隐私

- 插件不收集、不上传任何个人数据。
- 本地数据（`chrome.storage.local`）：签到设置、签到历史、统计数据、抽奖记录。卸载扩展时会一并清除。
- 同步数据（`chrome.storage.sync`）：仅在开启「同步到其他设备」时写入抽奖记录，存放在你自己的 Chrome 账号里。
- 所有对掘金的请求都在浏览器内直接发出，携带你当前登录的掘金 cookie。
